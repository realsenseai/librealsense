/ticket-to-pr — target flow

The user is asked for input only at the very end. Everything before that is a loop between the main agent and the two sub-agents.

User Main agent (holds design context, does all fixing) Sub-agent (fresh context, independent) Decision
  • Each loop is capped (review 4 rounds, test 3). If findings are still open at the cap, the flow stops and asks the user instead of looping forever.
  • A tester result of NOT RUN (no device available) is not a pass. It goes to the user, who can claim a lab machine.
  • The sub-agents never edit product code. Only the main agent does; the tester may edit only unit-tests/.
